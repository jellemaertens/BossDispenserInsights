Machine condition · all shops

One line per shop, from its latest backup. Shops with the most serious points come first. The figures cover the chosen period: channel status is worked out over it as on Channel health with that period, brush and colorant age are taken at its end. Canisters at minimum, the next piston and the backup are the state now. red = act now, amber = keep an eye on it. The points: Channels to check = channels with status Check on Channel health (an Autodrive 2 error in the last 30 days, self-test steps 35% above normal, or intake efficiency below 80%; amber from 3, red from 6); Pump < 10% = Autodrive 2 "pump filled less than 10%" errors (amber from 3, red from 10 per 30 days, scaled to the length of the period); Errors per 1,000 tints = machine errors, counting errors in the same minute once, against tints (amber at twice the median of all shops, red at four times, with at least 5 errors); Brush = tints since the last brush clean at the end of the period (amber over 150, red over 300; the dispenser asks for a clean after 100) and the median days between the cleans in the period; Oldest colorant = the oldest colorant age in a canister, with how many channels are past the age limit chosen on the Colorant age tab (no point: nearly every shop has a few slow colorants); Canisters at minimum (amber from 1, red from 3); Next piston = the soonest piston replacement on the Piston wear tab (red past the replacement point, amber within 60 days); Clock = events dated in the future, from a wrong dispenser clock (amber); they are left out of every figure, as are the few events dated 2000 that nearly every machine logs at start-up; and Backup older than 3 days (red after 14).

Pump filled less than 10% · all shops

Every shop backup on the file share is checked for the Autodrive 2 error pump filled less than 10%. New counts the errors logged since you last opened that shop or marked it as seen; this browser remembers that per shop. Contacted is shared with everyone: the ticks are kept in HA Dispenser Insights contacts.json on the file share, with who ticked them, and colleagues' ticks show up within a minute. A tick covers the errors logged up to that moment: a newer error clears it, so the shop shows as not contacted again. Opened without Start HA Dispenser Insights.cmd, the browser asks once for permission to save in the share folder and once for your name. Only backups that changed since the last scan are read again.

Travel counters as stored in each shop's latest backup, so the period does not change them; it does set the self-test steps. The database does not state the unit; technicians note it in metres. Pump travel counts over the life of the channel. Piston travel is the piston counter, which restarts at every piston replacement, with or without the tube. Piston & tube travel is the travel since the last "piston & tube replaced" entry: the database keeps no tube counter, so after a piston-only replacement it adds the travel the technician noted at that swap (e.g. "HPP vervangen 422.27m"); without a noted figure it shows "≥", a lower limit. A piston-only entry on the same day as a piston & tube entry counts as the same visit. Steps = Autodrive 2 "steps detect problem" from the daily self-test of that channel, in the chosen period, as on Channel health: Normal = median excluding the last 14 days, Last 14 d = average of the last 14 days with the change against normal, Weekly steps = weekly median. The export also lists the other counters and the last replacements. Open shows the shop's travel and steps for every channel.

Piston wear forecast · all shops

Every channel with a logged piston or piston & tube replacement, soonest due first. The piston counter restarts at each replacement. Replace at is the piston travel at which it should be replaced: by default the median of the travel technicians noted when they replaced one (e.g. "HPP vervangen 422.27m") on all scanned shops. Per day = piston travel per day since the last replacement; shortly after a replacement (less than 60 days) the travel noted at that replacement over the time since the one before is used, or else the pump travel per day since the log starts. Due = when the piston counter reaches the replacement point at that pace, counted from the last data in the backup. Channels that never had a logged replacement aren't listed: the counter of a part fitted before the log can't be tied to a replacement point. The forecast uses the counters at the time of the backup, as the database keeps no travel history; the period counts the replacements logged in it and marks them in period.

Colorant age · all shops

Colorant age in each canister at the end of the chosen period (or of the shop's backup, when that is earlier), worked out from the refills as on the Colorants tab: the colorant ages a day per day and every refill mixes fresh colorant in (age after = age before × litres before ÷ litres after). The age of what was in the canister when the log starts is unknown; while that could still be more than 5% of the canister the age shows as "≥", a minimum. Use per month = average over the chosen period. Months to use it up = litres in the canister now ÷ use per month: when that is long, the colorant keeps getting older, and a smaller refill or dropping the colorant at that shop could be considered. Click a colorant to list only its channels.

How reading a .mdf file works
  1. Start the tool with Start HA Dispenser Insights.cmd. When you open a database, it checks whether it_pos_app.exe is running and closes it, because the dispenser software locks the file. If you open this page directly, close the dispenser software yourself or use a backup copy of the file. The _Log.ldf file is not needed.
  2. Click Open .mdf file or drop the file anywhere on this page. The file is read inside your browser and is not uploaded anywhere.
  3. Type the shop name under Location. This browser remembers it for that machine's serial number.

The reader decodes the SQL Server data file directly, so no SQL Server or LocalDB is needed. It was checked row by row against SQL Server on an HA480 database (SQL Server 2012 file format). If a file can't be read, the page tells you why.
